# LexFinder KZ: поиск статей Трудового кодекса РК

Прототип интеллектуальной системы: по вопросу пользователя на русском языке возвращает наиболее релевантные статьи Трудового кодекса Республики Казахстан.

**Финальная модель:** гибрид BM25 + BGE-M3 dense (zero-shot), вес dense-части `w = 0.6`, подобран на dev. Версия `1.0.0`. Подробности, метрики и ограничения: [MODEL_CARD.md](MODEL_CARD.md).

## Архитектура

```
Браузер (static/index.html) ──HTTP──▶ FastAPI (lexfinder/api.py)
                                        │  валидация запроса (pydantic + normalize_query)
                                        ▼
                               LexFinder (lexfinder/engine.py)
                                 ├─ BM25 по title+chapter+text (227 статей)
                                 └─ BGE-M3 dense: эмбеддинги статей из index/doc_embeddings.npy,
                                    эмбеддинг запроса считается на лету
                                    score = w·z(dense) + (1−w)·z(bm25)
                                        │
                                        ▼
                               Monitor (lexfinder/monitoring.py): /metrics + logs/requests.jsonl
```

Если нейросетевая модель недоступна (`LEXFINDER_DENSE=auto`), сервис продолжает работать в режиме BM25 и честно сообщает об этом (`/health` → `degraded: true`, плашка в интерфейсе).

## Запуск

```bash
python -m venv .venv
source .venv/bin/activate          # Windows PowerShell: .\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python scripts/build_index.py --data data/lexfinder_labour_code.csv --out index   # один раз; скачивает BGE-M3 (~2.3 ГБ), несколько минут
uvicorn lexfinder.api:create_app --factory --host 0.0.0.0 --port 8000
```

Интерфейс: `http://localhost:8000/`, документация API (Swagger): `http://localhost:8000/docs`.

Без нейросети (быстрый режим для проверки): `LEXFINDER_DENSE=off uvicorn ...`.

Переменные окружения: `LEXFINDER_DATA`, `LEXFINDER_INDEX`, `LEXFINDER_DENSE` (`auto`/`on`/`off`), `DENSE_MODEL_REVISION` (хэш коммита модели на Hugging Face для фиксации версии), `LOG_DIR`, `LOG_QUERIES=1` (писать текст запросов в журнал; по умолчанию не пишется).

## API

| Метод | Путь | Описание |
|---|---|---|
| POST | `/search` | поиск статей |
| GET | `/health` | состояние, режим (`hybrid`/`bm25`), версия |
| GET | `/model-info` | версия, конфигурация, метаданные индекса |
| GET | `/metrics` | счётчики, задержки p50/p95, прокси-показатели качества, предупреждения |

**Вход** `POST /search`:
```json
{"query": "Как оплачивается работа ночью?", "top_k": 5}
```
`query`: строка 3–500 символов, содержит буквы или цифры (пробелы нормализуются); `top_k`: целое 1–20 (по умолчанию 5).

**Выход** (`200`):
```json
{"query": "...", "mode": "hybrid", "model_version": "1.0.0", "no_lexical_match": false, "latency_ms": 42.1,
 "results": [{"rank": 1, "article_number": "110", "title": "...", "chapter": "...", "score": 3.12, "snippet": "первые 300 символов статьи"}]}
```
`score`: безразмерная оценка гибрида (сравнивать можно только внутри одного ответа). `no_lexical_match=true`: в запросе нет слов, встречающихся в статьях, результат менее надёжен.

Ошибки: `422` (некорректный запрос или `top_k`, текст причины в `detail`), `500` (внутренняя ошибка, подробности в журнале сервера).

## Тестирование

```bash
pip install -r requirements-dev.txt
pytest -q
```
- `test_engine.py`: ранжирование, схема ответа, валидация входа, режим без лексических совпадений (на маленьком **синтетическом** фикстуре `tests/data/mini_articles.csv`, это не реальный текст закона);
- `test_api.py`: коды ответов, интерфейс, метрики, журнал, обработка внутренней ошибки;
- `test_golden_real.py`: Recall@5 на 34 размеченных запросах, запускается только если рядом лежит реальный CSV (порог 0.95 для hybrid, 0.80 для BM25).

## Мониторинг

`/metrics` отдаёт число запросов, отклонённых запросов и ошибок, задержки (p50, p95, max по последним 1000 запросам), среднюю оценку top-1 и долю запросов без лексического совпадения (признак смещения тем). Поле `warnings` содержит сработавшие предупреждения (высокая p95-задержка, много запросов без совпадений, рост ошибок, работа в запасном режиме BM25). Пороги заданы как начальные значения и не калибровались на реальном трафике. Каждый запрос пишется в `logs/requests.jsonl` (время, режим, задержка, хэш запроса, top-1 статья, оценка); текст запроса по умолчанию не сохраняется.

## Данные

`data/lexfinder_labour_code.csv`: 227 статей Трудового кодекса Республики Казахстан (колонки `article_number`, `title`, `chapter`, `text` и служебные), источник Adilet (`https://old.adilet.zan.kz/rus/docs/K1500000414`), редакция от 06.09.2026. Закон меняется: при обновлении текста нужно пересобрать индекс.

## Развёртывание

Проверено: локальный запуск (Windows, Python 3.11) в гибридном режиме на реальных данных и полный прогон в Google Colab (GPU T4): построение индекса, запросы к API, автотесты.
Для демонстрации с публичной ссылкой есть ноутбук `notebooks/LexFinder_KZ_Public_Demo.ipynb`: он поднимает сервис в Colab и выдаёт временную ссылку, которая работает, пока открыта сессия. Постоянного публичного хостинга у проекта нет.
Режим без нейросети (`LEXFINDER_DENSE=off`) работает на любой машине без скачивания модели, но с более низким качеством.
