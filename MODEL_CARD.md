# Model card: lexfinder-kz-hybrid v1.0.0

## Назначение
Ранжирование статей Трудового кодекса РК (227 статей) по вопросу пользователя на русском языке. Справочный инструмент, не юридическая консультация.

## Модель
Гибрид двух ранжировщиков, обучение не требуется:
- **BM25** по тексту `title + chapter + text` (k1 = 1.5, b = 0.75, простой стеммер: первые 5 символов слова);
- **BGE-M3 dense** (`BAAI/bge-m3`, zero-shot), документы кодируются как `title + ". " + text`, максимум 512 токенов, нормированные эмбеддинги, косинус.

Итоговая оценка: `score = w · z(dense) + (1 − w) · z(bm25)`, где `z(x) = (x − mean) / (std + 1e-9)`, `w = 0.6` (лучший вес на dev, 23 запроса, сетка 0…1 с шагом 0.05).

## Версионирование
- версия модели: `1.0.0` (`lexfinder/engine.py: MODEL_VERSION`), возвращается в каждом ответе, в `/health` и `/model-info`;
- индекс эмбеддингов сохраняется вместе с `index_meta.json`: модель, SHA-256 файла данных, число статей, версии библиотек, время сборки; при несовпадении данных и индекса сервис не использует устаревший индекс;
- точный снимок весов BGE-M3 фиксируется переменной `DENSE_MODEL_REVISION` (хэш коммита на Hugging Face); если не задана, в метаданных записано «unpinned».

## Вход и выход
**Вход:** `query` — строка 3–500 символов, содержит буквы или цифры; `top_k` — целое 1–20.
**Выход:** список из `top_k` статей: `rank`, `article_number`, `title`, `chapter`, `score`, `snippet`; а также `mode` (`hybrid`/`bm25`), `model_version`, `no_lexical_match`, `latency_ms`.
Некорректный вход отклоняется с понятным сообщением (HTTP 422), а не молча обрабатывается.

## Почему выбрана именно эта модель
Результаты на test (11 запросов, одни и те же для всех моделей; из ноутбука ASIK):

| Модель | Hit@1 | Recall@5 | MRR@5 |
|---|---|---|---|
| TF-IDF | 0.727 | 0.818 | 0.745 |
| BM25 | 0.818 | 0.909 | 0.848 |
| LogReg-реранкер (midterm) | 0.818 | 0.909 | 0.864 |
| BGE-M3 dense (zero-shot) | 0.818 | 1.000 | 0.894 |
| **Гибрид BM25 + BGE-M3 dense (w = 0.6)** | **0.909** | **1.000** | **0.927** |
| BGE-M3 dense+sparse+ColBERT (веса на dev) | 0.909 | 1.000 | 0.955 |
| BGE-M3 fine-tuned (+аугментация) | 0.909 | 1.000 | 0.955 |
| Qwen2.5-1.5B + QLoRA реранкер | 0.636 | 1.000 | 0.818 |

Лучшие по MRR@5 (0.955) модели обгоняют гибрид на один запрос из 11, что в пределах шума (доверительные интервалы bootstrap содержат 0). Гибрид выбран для эксплуатации по инженерным причинам: (1) не требует сохранённых весов дообучения (в эксперименте они не сохранялись) и дополнительной библиотеки FlagEmbedding; (2) использует один нейросетевой проход на запрос вместо трёх режимов BGE-M3; (3) естественно деградирует в BM25, если нейросеть недоступна. Если нужна максимальная точность на test, заменить модель на dense+sparse+ColBERT можно, но выигрыш не доказан статистически.

## Ограничения
- всего 34 размеченных запроса, по одной релевантной статье на запрос; test = 11 запросов, оценки шумные;
- вес `w` подобран на 23 dev-запросах; решение о выборе финальной модели принималось после просмотра таблицы test, поэтому оценка слегка оптимистична;
- ошибки возникают на смежных статьях одной темы;
- BM25-часть опирается на совпадение слов (стеммер примитивный); запросы с редкой лексикой помечаются `no_lexical_match`;
- закон меняется: данные (редакция кодекса) нужно обновлять и пересобирать индекс;
- качество в продакшене автоматически не измеряется (нет разметки), мониторятся только прокси-показатели.
